For the first device project, I decided to do a watering device with a browser interface showing the moisture data of my plant and allowing me to control the watering dynamic with a button.

Therefore, I need a cloud server. The expected pipeline will be: Arduino (MQTT client)→Cloud Server (MQTT broker + API)←Webpage(HTML/JS served via GitHub Pages).

1-Google Cloud Server

I managed to have a VM instance eqquiped with the MQTT broker running.

2-Arduino→Cloud Server

2.1-Wiring

Last week I had a try on a FSR becuase it needs some time for the moisture sensor to be shipped. Now it arrived and I need to change the FSR to the moisture sensor first.

2.2-Network Connection

For this week I am not going to work on the ouotput: the water pump. So I will just have the moisture data transmitted from Arduino to the dashboard and also backwards (maybe just a console log when the Arduino receives the watering command).

3-Cloud Server←Webpage

I added a Node.js environment on my VM to translate between MQTT and HTTP, guaranteeing the communication between the cloud server and the webpage.

And then I deployed a HTTPS api. Now, the pipeline is built:

I can see the real time data in different devices with only one url link, even if the devices are not connected to my home wifi.
